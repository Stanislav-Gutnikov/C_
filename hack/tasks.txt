Для каждого задания я даю уязвимый код на Си, флаги компиляции и вектор атаки. Твоя задача — скомпилировать их локально и сломать.Задание 1. Изменение логики (Variable Hijacking)Цель: Понять, что переполнение буфера может не только затирать адреса возврата, но и менять переменные, управляющие логикой программы.Суть: В стеке локальные переменные лежат вплотную друг к другу. Переполнив одну, можно изменить значение соседней.Исходный код (task1.c)c#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    volatile int modified = 0;
    char buf[16];

    if (argc < 2) {
        printf("Использование: %s <пароль>\n", argv[0]);
        return 1;
    }

    strcpy(buf, argv[1]);

    if (modified == 0x1337) {
        printf("[SUCCESS] Доступ администратора получен! Вы взломали переменную.\n");
    } else {
        printf("[FAIL] Обычный пользователь. modified = 0x%x\n", modified);
    }
    return 0;
}
Используйте код с осторожностью.Компиляция: gcc -fno-stack-protector -no-pie -O0 task1.c -o task1Подсказка: Посмотри в GDB расстояние от buf до modified. Тебе нужно заполнить буфер мусором, а затем передать число 0x1337 в формате Little-Endian.Задание 2. Уязвимость строки формата (Format String Bug)Цель: Научиться читать и писать в память вообще без переполнения буфера, используя ошибку функций семейства printf.Суть: Если передать пользовательский ввод напрямую в printf(buf) вместо printf("%s", buf), процессор начнет воспринимать спецсимволы (вроде %x или %n) как команды для чтения/записи стека.Исходный код (task2.c)c#include <stdio.h>
#include <string.h>

int main() {
    char secret_flag[] = "FLAG{fmt_str_master_2026}";
    char buf[128];

    printf("Введите ваше имя: ");
    fgets(buf, sizeof(buf), stdin);
    
    // КРИТИЧЕСКАЯ ОШИБКА: Нет спецификатора формата %s
    printf(buf); 
    return 0;
}
Используйте код с осторожностью.Компиляция: gcc -no-pie -O0 task2.c -o task2 (stack protector можно не отключать, атака его не трогает).Подсказка: Твоя задача — вытащить скрытый флаг secret_flag из памяти. Передавай в программу строку, состоящую из множества спецификаторов %p или %x через пробел (например, %p %p %p %p %p). Программа начнет выплевывать адреса и данные со стека. Найди, на каком шаге покажутся ASCII-коды флага.Задание 3. Обход проверки знака (Integer Underflow)Цель: Закрепить то, о чем мы говорили ранее — обход логических проверок размера с помощью математических особенностей процессора.Исходный код (task3.c)c#include <stdio.h>
#include <string.h>
#include <stdlib.h>

void backdoored_function() {
    printf("[SUCCESS] Вы обошли проверку размера и переполнили буфер!\n");
}

int main(int argc, char *argv[]) {
    char buf[32];
    
    if (argc < 3) {
        printf("Использование: %s <размер> <данные>\n", argv[0]);
        return 1;
    }

    int user_size = atoi(argv[1]);

    // Программист пытается защитить буфер
    if (user_size > 32) {
        printf("[FAIL] Размер слишком велик! Максимум 32.\n");
        return 1;
    }

    // memcpy принимает размер как тип size_t (беззнаковое число)
    memcpy(buf, argv[2], user_size);
    return 0;
}
Используйте код с осторожностью.Компиляция: gcc -fno-stack-protector -no-pie -O0 task3.c -o task3Подсказка: Передай в качестве первого аргумента отрицательное число (например, -1). Для проверки if (user_size > 32) оно будет меньше 32, и программа пропустит его. Но внутри memcpy оно превратится в гигантское положительное число, что вызовет жесткое переполнение буфера. Используй это, чтобы затереть адрес возврата адресом backdoored_function.Задание 4. Поиск утечки адреса (ASLR Bypass / Information Leak)Цель: Научиться взламывать программы, когда включена защита ASLR (когда адреса случайны при каждом запуске).Суть: Нельзя прыгнуть на функцию, если ты не знаешь, где она. Но если программа из-за ошибки (например, строки формата) случайно напечатает хотя бы один реальный адрес из памяти, хакер может вычислить базовый адрес загрузки (Base Address) и восстановить все остальные адреса.Исходный код (task4.c)c#include <stdio.h>
#include <string.h>

void win() {
    printf("[SUCCESS] ASLR обойден! Функция win() выполнена.\n");
}

void vuln() {
    char buf[64];
    printf("Локальный буфер находится тут: %p\n", buf); // Программа сама «сливает» адрес!
    
    printf("Введите данные: ");
    gets(buf); // Уязвимость
}

int main() {
    vuln();
    return 0;
}
Используйте код с осторожностью.Компиляция: Включи ASLR обратно: sudo sysctl -w kernel.randomize_va_space=2. Скомпилируй программу без флага -no-pie: gcc -fno-stack-protector -O0 task4.c -o task4.Подсказка: Поскольку -no-pie отсутствует, адреса win и buf меняются при каждом запуске. Однако расстояние (смещение/offset) между функцией win() и буфером buf в памяти всегда остается абсолютно одинаковым. Зайди в GDB, посмотри адрес win и адрес buf, найди разницу между ними. Твой Python-скрипт должен сначала прочитать адрес из вывода программы, прибавить/вычесть эту разницу и динамически сформировать идеальный payload.Задание 5. Атака на кучу (Use-After-Free / Heap Basics)Цель: Выйти за пределы стека и понять, как устроена уязвимость в динамической памяти (Куче / Heap).Суть: Когда память освобождается через free(), но указатель на нее не зануляется, программа может продолжить использовать этот адрес. Если в эту же область памяти выделится новый объект, данные перепутаются.Исходный код (task5.c)c#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct User {
    char name[16];
    void (*print_role)(); // Указатель на функцию, выводящую роль
};

void normal_user() { printf("Роль: Обычный пользователь\n"); }
void admin_user()  { printf("[SUCCESS] Роль: АДМИНИСТРАТОР СИСТЕМЫ!\n"); }

int main() {
    struct User *u = malloc(sizeof(struct User));
    u->print_role = normal_user;

    printf("1. Освобождаем память пользователя...\n");
    free(u); 
    // ОШИБКА: указатель 'u' не занулен (Dangling Pointer)

    printf("2. Выделяем память под секретные данные хакера...\n");
    char *hacker_data = malloc(24);
    
    printf("Введите данные хакера: ");
    fgets(hacker_data, 24, stdin); // Мы пишем в ту же область памяти!

    printf("3. Программа пытается проверить роль старого пользователя:\n");
    u->print_role(); // Вызов по старому указателю
    return 0;
}
Используйте код с осторожностью.Компиляция: gcc -no-pie -O0 task5.c -o task5Подсказка: Менеджер памяти Linux повторно использует только что освобожденные блоки. Переменная hacker_data займет ровно то место в куче, где лежал struct User. Первые 16 байт твоего ввода запишутся вместо name, а следующие 8 байт перезапишут указатель на функцию print_role. Передай туда адрес функции admin_user.
